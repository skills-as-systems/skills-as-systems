# SITECRAFT architecture maintenance — compact

Use when evolving SITECRAFT. Keep changes provider-neutral, backwards-compatible, optional, and lightweight.

## Continuity and direction
Use `continuity_system` only for real cross-surface/state/asset/agent continuity; handoffs may carry IDs but never replace the Experience Contract. Use `visual_grammar.direction_selection` only when direction is open: `exploring` needs two structurally different arguments, `converged` selects one, `not_needed` avoids fake options.

## Review and evidence
Review defects/floors before scores. Self/fresh-context reviews are not independent; automated checks prove only stated scope. Escalate diagnostics only for an unexplained real defect or deeper proof need, then stop once cause/proof is clear.

## Learning promotion
One project never creates doctrine. Promotion needs counterexample risk, contrasting/stronger external evidence, explicit `approved_for_promotion`, a bounded target, and preserved source evidence. Translate learned mechanisms into current project rules, not a second design system.
